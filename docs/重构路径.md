# Libra-Nextgen 重构路径 —— 对标 Havoc，迈向可商业化 C2

> 本文档只存于 `docs/`（已被 .gitignore 排除，不并入版本库）。
> 目标：系统梳理我们要向 Havoc 学习什么、具体到源码文件，并给出可执行的阶段计划。

---

## 0. 结论先行

我们和 Havoc 的差距，本质是 **Web 工程能力 vs 免杀工程能力** 的分野：

| | Havoc | Libra-Nextgen |
|---|---|---|
| Agent 免杀 | 开源第一梯队（间接 syscall / 三系 sleep 混淆 / HWBP patchless AMSI-ETW） | 裸奔（直接 FFI / 明文内存 / 无 AMSI-ETW patch） |
| 服务端架构 | 事件源 + 二进制协议 + SQLite（无 RBAC、明文密钥） | REST + WS + MongoDB（有 RBAC、审计、JWT） |
| 客户端 | Qt 单机多进程（无 RBAC、无虚拟列表、无 PTY） | Web 多人（天然协同、虚拟列表、xterm.js PTY） |
| 商业化就绪 | 低（无权限管控、明文 secret、单文件 DB） | 高（RBAC + 审计 + 插件体系） |

**路线：用 Havoc 的免杀技术武装我们的 Agent，用我们已有的 Web 架构 + RBAC + 插件体系作为商业化护城河。**

---

## 1. 现状诊断（我们缺什么，按致命程度排序）

### 1.1 Agent 免杀（致命，最高优先级）

| 能力 | 我们现状 | Havoc | 后果 |
|---|---|---|---|
| 间接 syscall | ❌ 直接 FFI 调 ntdll 导出 | ✅ HellsGate+HalosGate | 所有 Nt* 调用被 EDR inline hook 拦截 |
| Sleep 混淆 | ❌ 普通 sleep | ✅ Ekko/Zilean/Foliage | sleep 期间明文内存被 EDR 扫描 |
| AMSI/ETW patch | ❌ 无 | ✅ 硬件断点 patchless | PowerShell/反射加载被 AMSI 扫出 |
| Return address spoofing | ❌ 无 | ✅ AceLdr 式 gadget | syscall 返回栈被 EDR 回溯 |
| Token Vault | ⚠️ 仅 DuplicateTokenEx（浏览器凭据） | ✅ 完整 vault | 无法横向移动 |
| 进程注入 | ❌ 无独立模块 | ✅ 反射 DLL + NtCreateThreadEx | 无法迁移进合法进程 |

### 1.2 服务端架构（中等）

| 能力 | 我们现状 | Havoc | 改进方向 |
|---|---|---|---|
| Malleable profile | ⚠️ 硬编码 C# 类 | ✅ HCL 声明式 | JSON Schema 声明式 |
| RequestID 校验 | ⚠️ 有 rid 关联，未校验真实性 | ✅ IsKnownRequestID | 加严格校验 |
| 会话密钥持久化 | ❌ 内存态，重启丢 | ✅ SQLite 落库 | Mongo 持久化 |
| 事件溯源同步 | ❌ 广播+各自拉 REST | ✅ EventsList 回放 | 有序事件日志 |

### 1.3 客户端交互（低优先级，锦上添花）

| 能力 | 我们现状 | Havoc |
|---|---|---|
| Session Graph | ❌ 设计有未实现 | ✅ Qt 自绘树（绿/紫/红边） |
| Loot 库 | ❌ 无 | ✅ 截图图库 + 下载登记 |
| Event Viewer | ⚠️ 后端审计有，无实时 UI | ✅ 全局事件流 |

## 2. 总体路线（Phase → 版本映射）

```
Phase 1 (v1.4.0)  Agent 免杀地基：间接 syscall + RequestID 校验
Phase 2 (v1.5.0)  Sleep 混淆 + AMSI/ETW patch
Phase 3 (v1.6.0)  Token Vault + 凭据增强
Phase 4 (v1.7.0)  声明式 Profile + 会话密钥落库
Phase 5 (v1.8.0)  Session Graph + Loot + Event Viewer + 事件溯源
Phase 6 (v1.9.0)  BOF 生态 + SMB pivot + 多 payload 格式
```

依赖关系：
- Phase 1 是所有免杀的地基（2/3 都依赖它）
- Phase 3 是横向移动的前提
- Phase 6 的 SMB 依赖 Phase 1 的多传输抽象
- Phase 4/5 相对独立，可与 1/2 并行

## 3. Phase 1 —— Agent 免杀地基（v1.4.0）

### 3.1 目标
- Agent 所有 Nt* 调用改为**间接 syscall**，绕过 EDR 的 ntdll inline hook
- 服务端加 **RequestID 真实性校验**

### 3.2 学习 Havoc 源码（具体到文件）

| Havoc 文件 | 关键函数 | 我们要学什么 |
|---|---|---|
| `payloads/Demon/src/core/Syscalls.c` | `SysExtract`（:90）| 字节模式扫描 `4C 8B D1 B8`（`mov r10,rcx; mov eax,imm32`）提取 SSN；`SYS_RANGE` 内搜 `0F 05`（syscall 指令地址） |
| `payloads/Demon/src/core/Syscalls.c` | `FindSsnOfHookedSyscall`（:201）| HalosGate 邻居推导：用相邻 Nt 函数的 SSN ± 偏移反推被 hook 函数的 SSN |
| `payloads/Demon/src/core/Syscall.x64.asm` | `SysInvoke`（:13）| 间接调用 stub：`mov r10,rcx / mov eax,[r11+8] / jmp [r11]` |
| `payloads/Demon/include/core/Syscalls.h` | `SYSCALL_INVOKE` 宏（:12）| 自动降级：间接 syscall 失败时降级到 Win32 直调 |
| `teamserver/pkg/agent/demons.go` | `IsKnownRequestID` | 回包 rid 必须存在于已下发的 Tasks 中，否则丢弃 |

### 3.3 我们的实现方案（Rust）

**新建 crate：`src/agent-rs/libra-syscalls/`**

1. **SSN 提取（HellsGate）**
   - 读 `ntdll.dll` 内存（`GetModuleHandleW("ntdll")` + PE 解析 .text 段）
   - 扫描 stub 字节：`4C 8B D1 B8 ?? ?? ?? ??`，SSN = 第 4~5 字节（u16）
   - 在 stub 后 `0x1E` 字节内找 `0F 05`，取该地址作为间接跳转目标

2. **邻居推导（HalosGate）**
   - 某 Nt 函数 SSN 提取失败 → 认为被 hook
   - 用 `GetSyscallSize`（相邻导出函数地址差）上下扫描，找到最近未 hook 的 stub
   - 用其 SSN ± 偏移推导目标 SSN

3. **间接调用**
   - Rust 用 `std::arch::asm!` 或 `global_asm!` 写 `SysInvoke` stub
   - 结构：`{ syscall_addr: *const u8, ssn: u16 }`
   - 封装 `nt_open_process` / `nt_allocate_virtual_memory` / `nt_write_virtual_memory` 等 40 个常用 Nt*

4. **统一入口**
   - 定义 trait `SyscallInvoker`，替换现有 `libra-modules` / `libra-platform` 里的直接 FFI
   - 所有 `windows-sys` 或手写 FFI 的 Nt* 调用，改为走间接 syscall

5. **RequestID 校验**
   - `RelayService` 加 `HashSet<string> issuedRequestIds`
   - `RelayAndWaitAsync` 下发前登记 rid；`CompletePendingRequest` 校验 rid 已登记才完成
   - 未登记的 rid 回包直接丢弃 + 记审计日志

### 3.4 验收标准
- 抓取 Agent 进程内存，确认 Nt* 调用不再经过 ntdll 导出函数头
- 用 EDR 测试工具（或自建 inline hook）验证 hook 失效
- 伪造一个未下发的 rid 回包，服务端正确丢弃并记日志

## 4. Phase 2 —— Sleep 混淆 + AMSI/ETW patch（v1.5.0）

### 4.1 目标
- sleep 期间加密整个 Agent 镜像（RX→RW→RC4 加密→解密→RX）
- AMSI/ETW 用硬件断点 patchless 绕过

### 4.2 学习 Havoc 源码

| Havoc 文件 | 关键函数 | 我们要学什么 |
|---|---|---|
| `payloads/Demon/src/core/Obf.c` | `FoliageObf`（:22）| APC-ROP 链：`ConvertThreadToFiberEx` + `CreateFiberEx` + `NtContinue` 逐 CONTEXT 执行 ROP |
| `payloads/Demon/src/core/Obf.c` | `TimerObf`（:339）| Ekko（`RtlCreateTimerQueue`+`RtlCreateTimer`）/ Zilean（`NtCreateEvent`+`RtlRegisterWait`），回调= `NtContinue` |
| `payloads/Demon/src/core/Obf.c` | `JmpBypass`（:459）| CFG 绕过：ntdll 里搜 `FF E0`(jmp rax)/`FF 23`(jmp [rbx]) gadget |
| `payloads/Demon/src/core/Obf.c` | StackSpoof（:506）| NT_TIB 伪造：换线程的 TIB 让栈回溯错乱 |
| `payloads/Demon/src/core/HwBpEngine.c` | `HwBpEngineSetBp`（:61）| Dr0-3 硬件断点 + Dr7 置位，`NtSetContextThread` 写回 |
| `payloads/Demon/src/core/HwBpExceptions.c` | `HwBpExAmsiScanBuffer`（:6）| VEH 上下文替身：改栈参数让 AmsiScanBuffer 空跑返回 CLEAN |
| `payloads/Demon/src/core/Spoof.c` | `SpoofRetAddr`（:6）+ `Spoof.x64.asm` | gadget 栈替换，返回地址指向 kernel32 合法指令 |

### 4.3 我们的实现方案（Rust）

**Sleep 混淆（先做 Ekko，再补 Foliage）**

1. 用 `std::arch::asm!` 写 `RtlCaptureContext` / `NtContinue` 的桥接
2. 实现 ROP 链：
   - 每个链节 = 完整 `CONTEXT`（RIP=目标 API，寄存器/栈摆参数）
   - 链：`NtProtectVirtualMemory(RW)` → `SystemFunction032(RC4 加密镜像)` → `WaitForSingleObjectEx(sleep)` → `SystemFunction032(解密)` → `NtProtectVirtualMemory(RX)` → `NtSetContextThread(还原)`
3. Timer 触发：`RtlCreateTimerQueue` + `RtlCreateTimer`，回调 = `NtContinue`
4. RC4 密钥每次随机 16 字节

**AMSI/ETW patch（硬件断点 patchless）**

1. `RtlAddVectoredExceptionHandler` 注册 VEH（第一位）
2. 对 `AmsiScanBuffer` / `NtTraceEvent` 入口下 Dr0/Dr1 断点（`NtGetContextThread`+`NtSetContextThread`，走 Phase 1 的间接 syscall）
3. VEH 里匹配 `STATUS_SINGLE_STEP` → 撤断点 → 伪造返回值（AmsiScanBuffer 返回 E_INVALIDARG + 结果=0）→ 恢复断点 → `EXCEPTION_CONTINUE_EXECUTION`

**Return address spoofing**

1. kernel32 里找 `FF 23`（jmp [rbx]）gadget
2. 调敏感 API 前，把栈顶返回地址换成 gadget，真返回地址存参数块
3. 汇编 stub 实现（`Spoof.x64.asm` 的 Rust 版）

### 4.4 验收标准
- sleep 期间 dump 内存，镜像 `.text` 段不可读（已加密）
- PowerShell 执行绕过 AMSI（测试脚本不再被拦截）
- ETW 日志无 Agent 相关事件

## 6. Phase 4 —— 声明式 Profile + 会话密钥落库（v1.7.0）

### 6.1 目标
- Malleable Profile 从硬编码类改为 JSON Schema 声明式
- SessionKeyStore 持久化到 Mongo（服务重启不丢 session）

### 6.2 学习 Havoc 源码

| Havoc 文件 | 我们要学什么 |
|---|---|
| `teamserver/pkg/profile/config.go` | 配置结构体设计（Server/Operators/Listeners/Demon 分块） |
| `teamserver/pkg/profile/profile.go` | `SetProfile` 解析入口，一份配置三处消费 |
| `teamserver/pkg/handlers/http.go` | 服务端指纹三重校验（Headers/Uris/UA），失败统一 fake404 |
| `teamserver/pkg/db/agents.go` | TS_Agents 表存 AESKey/AESIv(base64)，重启恢复 session |
| `teamserver/cmd/server/teamserver.go` | 启动时 `AgentAll()` 恢复 + 重建 pivot 拓扑 |

### 6.3 我们的实现方案

**声明式 Profile（JSON Schema）**

1. 定义 `profile.schema.json`：
   ```jsonc
   {
     "name": "teams-mimic",
     "listeners": [{
       "type": "http",
       "hosts": ["5pider.net"],
       "hostRotation": "round-robin",
       "portBind": 443,
       "portConn": 443,
       "secure": true,
       "killDate": "2026-12-31 00:00:00",
       "userAgent": "...",
       "uris": ["/Collector/2.0/settings/"],
       "headers": {...},
       "response": { "headers": {...}, "mimic": "json" }
     }],
     "demon": { "sleep": 2, "jitter": 15, "injection": {...} }
   }
   ```
2. 替换 `DefaultProfile` / `MalleableProfileConfig`
3. 服务端加载 active profile，Agent 注册时下发 profile 配置
4. 服务端也做指纹校验（不信任 agent 自约束）

**会话密钥落库**

1. `SessionKeyStore` 从内存改为 Mongo 持久化
2. 新集合 `session_keys`：`{ agentId, key, iv, createdAt }`
3. 服务启动时从 Mongo 恢复 session key
4. Agent 重连时直接复用旧 key（无需重新 RSA 协商）

### 6.4 验收标准
- 切换 profile 后抓包，流量路径/头部/响应头完全变形
- 服务重启后 Agent 无需重新上线，session 保持
- 非 profile 路径访问返回伪装 404

## 9. 依赖关系与并行策略

```
Phase 1（间接 syscall）───┐
                          ├──> Phase 2（sleep 混淆/AMSI）依赖 1
Phase 4（Profile）        ├──> Phase 3（Token）依赖 1
Phase 5（前端）           ├──> Phase 6（SMB）依赖 1 + 3
```

- **Phase 1 必须先做**，它是 2/3/6 的地基
- **Phase 4/5 可与 1/2/3 并行**（服务端/前端，不依赖 Agent 免杀）
- **Phase 6 的 SMB 依赖 Phase 1 的传输抽象 + Phase 3 的 token**

## 10. 风险与注意事项

1. **Rust 写间接 syscall 的难点**：Rust 没有 C 的 `__builtin_return_address` 和自由 inline asm，需要用 `std::arch::asm!` 或 `global_asm!`，且要处理 Rust 的调用约定。
2. **Sleep 混淆的 ROP 链**：CONTEXT 级 ROP 编程极难调试，建议先做 Ekko（timer 版，相对简单），再做 Foliage（APC 版）。
3. **HWBP 的固有弱点**：只有 4 个硬件断点（Dr0-3），EDR 可轮询调试寄存器发现。这是 Havoc 也承认的弱点，我们做的时候要有预期。
4. **安全红线**：LSASS 读取、token 窃取、进程注入都属于高危操作，必须走 RBAC + 审计，且仅授权场景可用（符合项目免责声明）。
5. **不要照搬 C 代码**：Havoc 是 C/ASM，我们是 Rust，要理解原理后用 Rust 重写，而非逐行翻译。
